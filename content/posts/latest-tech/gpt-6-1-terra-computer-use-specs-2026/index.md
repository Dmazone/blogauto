## GPT-6.1 Terra 등장 배경과 주요 스펙

기존 멀티모달 모델들은 화면 스크린샷의 텍스트와 좌표를 읽는 과정에서 극심한 연산 지연과 클릭 미스를 겪었습니다. 이번 릴리즈는 연산 그래프 자체를 시각적 데스크톱 상호작용에 맞춰 전면 재설계하면서 기존의 병목 구간을 확실하게 뚫어냈습니다.

### 전작 대비 시각 추론 및 연산 효율 개선점

이전 세대는 고해상도 전체 화면을 통째로 잘게 쪼개어 토큰화하느라 불필요한 GPU 자원을 낭비했습니다. 반면 이 모델은 마우스 커서 주변이나 UI 구성 요소가 실시간으로 변하는 영역만 선별해 처리하는 '어텐티브 패치(Attentive Patch)' 방식을 채택했습니다.

- **프레임 처리 속도 개선**: 화면 갱신에 따른 프레임 인지 속도를 직전 버전 대비 3.2배 단축
- **적응형 시각 엔진**: 4K 멀티모니터 환경에서도 왜곡 없이 8포인트 이하 미세 폰트까지 판독
- **초저지연 반응 속도**: 클릭 및 타이핑 인터랙션 피드백 루프를 평균 180ms 안쪽으로 압축

### OSWorld 2.1 벤치마크 점수와 컴퓨터 제어 성능

실제 운영체제 안에서 복합 과제를 수행하는 글로벌 표준 평가인 OSWorld 2.1 벤치마크에서 68.4%의 성공률을 기록했습니다. 이는 인간 작업자 평균치(72.3%) 턱밑까지 따라붙은 결과이자, 직전 세대 대비 24%p 이상 치솟은 수치입니다.

> 압축 파일을 풀고, 엑셀 시트에서 특정 조건의 열만 추출한 뒤, 사내 웹 인트라넷 폼에 오차 없이 일괄 붙여넣는 15단계 연속 작업을 사람의 손길 한 번 없이 매끄럽게 마쳤습니다.

단순 브라우징을 넘어 그래픽 툴의 레이어 정리나 터미널 콘솔 명령어 실행 등 데스크톱 전반의 실무 워크플로우를 그대로 소화합니다.

### 토큰당 비용 절감과 API 공급 정책

화면 제어 작업은 주기적인 캡처 화면 전송이 필수라 자칫 API 비용이 눈덩이처럼 불어나기 십상입니다. OpenAI는 화면 입력 캐싱(Vision Caching) 알고리즘을 적용해 반복되는 정적 배경 요소의 입력 토큰 비용을 80% 깎아냈습니다. 여기에 초당 프레임 처리량을 안정적으로 보장하는 전용 인스턴스 옵션을 묶어 대규모 웹 스크래핑과 모니터링 환경에 대응합니다.

전통적인 RPA 도구는 특정 버튼의 고정 좌표값이나 웹 DOM 셀렉터 트리 구조에 기댔습니다. 웹사이트 디자인이 조금만 바뀌어도 즉각 멈춰 서던 취약점을 **GPT-6.1 Terra**는 시각적 맥락 이해로 풀어냅니다.

### 화면 픽셀 인지와 마우스·키보드 조작 방식

운영체제의 가상 드라이버 인터페이스를 타고 들어가 인간이 책상 앞에서 작업하는 방식을 그대로 모사합니다.

- **상대 좌표 추론**: 버튼의 절대 좌표 대신 주변 텍스트와 레이아웃 맥락을 읽어 클릭 위치 계산
- **단축키 및 드래그 지원**: 복합 단축키는 물론 파일 드래그 앤 드롭, 정밀 스크롤을 자연스럽게 조합
- **동적 렌더링 추적**: 로딩 아이콘이 사라지고 실제 화면 요소가 뜨는 타이밍을 시각적으로 확인한 뒤 다음 동작 개시

웹 브라우저 소스코드를 뜯지 않고 모니터에 출력된 그래픽만을 바라보며 동작하기 때문에, 사내 레거시 ERP나 C/S 기반 폐쇄망 소프트웨어에서도 막힘없이 작동합니다.

### 예외 팝업과 비정형 웹 UI 대응력 비교

기존 매크로는 돌발적인 세션 만료 알림이나 시스템 경고창을 마주하면 뻗어버렸습니다. 이 모델은 불시에 튀어나오는 창의 의도를 스스로 파악합니다. 단순 이벤트 팝업은 '닫기'를 누르고, 재인증 창이 뜨면 사내 보관함 경로를 거쳐 2차 인증을 통과한 뒤 원래 하던 창으로 포커스를 돌려놓습니다.

### 복합 멀티스텝 작업에서의 자율 수정 프로세스

명령어를 실행하다 오타를 내거나 엉뚱한 메뉴를 눌렀을 때 스스로 이를 바로잡는 자가 교정(Self-Correction) 메커니즘을 갖췄습니다. 기대와 다른 화면이 출력되면 Ctrl+Z를 누르거나 뒤로 가기를 실행한 뒤 우회 메뉴를 찾아냅니다. 고정 규칙 기반 프로그램으로는 감당할 수 없던 장기 작업(Long-horizon Tasks)을 안정적으로 끝맺는 이유입니다.
