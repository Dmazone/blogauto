## 1. 퍼포먼스 마케팅 데이터 추적 아키텍처 개요

정확한 마케팅 성과 측정과 전환 최적화를 위해서는 웹사이트 전반에 일관된 이벤트 추적 환경을 구축해야 합니다. 클라이언트 사이드 트래킹의 데이터 유실을 보완하기 위해 Google Tag Manager(GTM)와 서버 사이드 API 연동을 병행하는 하이브리드 구조가 표준으로 자리 잡았습니다.

* **데이터 레이어(dataLayer) 표준화**: 유저 인터랙션 발생 시 공통 변수(페이지 경로, 유저 세그먼트, 이벤트 액션 등)를 일관되게 적재
* **GTM 웹 컨테이너**: GA4, Meta Pixel, 네이버/카카오 전환 스크립트 등 서드파티 태그를 중앙에서 통제
* **CAPI(Conversions API) 연동**: 브라우저 쿠키 제한 환경(ITP 등)에서도 서버 간 직접 통신을 통해 결제 및 상담 신청 데이터 누락 방지

## 2. 핵심 전환 이벤트 및 파라미터 설계

전환 퍼널(Funnel)을 세분화하여 각 단계별 이탈률과 최종 목표 달성률을 명확히 추적합니다. 리드 수집형 및 수강 신청 랜딩페이지에 최적화된 표준 이벤트 정의는 다음과 같습니다.

| 단계 | 이벤트명 | 주요 파라미터 | 트리거 조건 |
| :--- | :--- | :--- | :--- |
| 탐색 | `view_content` | `branch_name`, `course_category` | 상세 커리큘럼 페이지 도달 |
| 문의 | `lead_inquiry` | `course_id`, `inflow_channel` | 1:1 상담 폼 제출 버튼 클릭 |
| 접수 | `generate_lead` | `lead_id`, `branch_name`, `value` | 상담 접수 완료 페이지(Thank-you) 진입 |
| 최종 | `complete_registration` | `transaction_id`, `course_name` | 수강 결제 또는 최종 승인 완료 |

## 3. GTM 및 Meta Pixel 트리거 설정 가이드

웹 환경에서 발생하는 유저 인터랙션을 정확하게 포착하기 위해 사용자 정의 이벤트와 DOM 요소를 활용한 트리거링 규칙을 적용합니다.

* **상담 폼 제출 트리거**: 단순 클릭 추적(`gtm.click`) 대신 `form_submit` 이벤트나 완료 메시지 DOM 노출(`Element Visibility`)을 기준으로 설정하여 중복 집계 방지
* **스크롤 뎁스 추적**: 25%, 50%, 75%, 90% 임계점 도달 시 `scroll_depth` 이벤트를 발송하여 랜딩페이지 가독성 및 이탈 지점 분석
* **외부 링크 및 전화 문의 클릭**: `Click URL` 변수에 `tel:` 또는 오픈채팅 링크가 포함된 경우를 포착하여 전환 가치 부여

## 4. 데이터 검증 및 QA 프로세스

태그 배포 전 디버깅 모드를 활용하여 파라미터 유실 및 오작동 여부를 전수 검사합니다.

* **GTM Preview 모드 검증**: 각 전환 액션 실행 시 의도한 태그만 단일 실행(`Fired Once`)되는지 확인
* **Meta Pixel Helper & GA4 DebugView**: 브라우저 확장 프로그램 및 실시간 디버그 화면을 통해 파라미터 페이로드(Payload) 정합성 확인
* **서버-클라이언트 중복 제거(Deduplication)**: Meta Pixel의 브라우저 이벤트와 CAPI 이벤트가 동일한 `event_id`를 공유하도록 설정하여 전환 중복 카운팅 방지
